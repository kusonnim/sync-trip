# [해커톤 기획서] 소셜 투표 기반 '타임 윈도우' 여행 동선 최적화 서비스 (가제: SyncTrip)

## 1. 서비스 개요 (Background & Problem)

* **타깃 고객:** 단체 여행(MT, 우정 여행 등)을 기획하는 대학생 및 2030 그룹.
* **해결하려는 문제 (Pain Point):**
1. **소셜 제약:** 단톡방에 장소 링크만 무분별하게 공유되며, 의견 취합과 일정 확정이 어렵다.
2. **기존 서비스의 한계:** '트리플' 등 기존 여행 앱은 단순 **거리순 정렬**만 지원하여, "특정 식당은 저녁 6시 예약", "미술관은 5시 마감" 같은 시간 제약(Time-Windows)을 반영하지 못한다. 대중교통 노선 역시 일정 툴과 분리되어 있어 별도로 검색해야 한다.


* **해결책 (Solution):** 그룹원이 실시간으로 장소를 투표하여 후보를 좁히고, 해당 장소들의 영업시간 및 사용자 예약 시간 제약을 융합 분석해 **이동 시간을 최소화하면서도 시간 제약을 완벽히 지키는 대중교통/자차 맞춤형 타임라인을 자동 생성**한다.

---

## 2. 핵심 사용자 시나리오 (User Flow)

1. **초간편 방 개설 및 접속:** 로그인 없이 '4자리 방 코드'와 '닉네임'만으로 세션에 접속.
2. **장소 장바구니 및 실시간 투표:** 팀원들이 가고 싶은 장소를 검색해 리스트에 추가하고, 1인당 제한된 하트(좋아요)를 사용하여 투표 진행. 실시간으로 득표순 상위 장소(5~7개) 확정.
3. **하이브리드 제약 조건 설정 (API + 수동 덮어쓰기):**
* **자동(API):** 확정된 장소들의 기본 영업시간을 구글 Places API 등을 통해 1차로 불러옴.
* **수동(Override):** API 데이터가 누락되었거나(null), "저녁 6시 식당 예약"처럼 특별한 제약이 필요한 경우 방장이 직접 방문 시간을 수동 입력하여 덮어쓰기 진행.


4. **AI 동선 최적화 연산 및 타임라인 생성:** 이동 수단(자차 or 대중교통)을 선택하면 알고리즘이 연산하여 늦지 않고 가장 동선이 짧은 순서를 실제 길찾기 노선과 함께 '타임라인 UI'로 출력.

---

## 3. 주요 기획 디테일 및 정책 (Feature Details)

* **출발/도착 분리 및 데드라인 설정:** 출발지와 최종 도착지를 다르게 설정할 수 있으며, '출발 시간'과 '여행 종료 데드라인(예: 21시 전에는 해산)'을 개별적으로 지정 가능.
* **유연한 체류 시간(Stay Time) 정책:** 장소 카테고리별로 기본 체류 시간(예: 1시간)을 제공하되, 사용자가 장소별로 '최소 체류 시간'과 '최대 체류 시간'을 수정할 수 있도록 하여 알고리즘에 유연성을 부여.
* **스마트 에러 핸들링 (충돌 경고):** 물리적으로 불가능한 일정(예: A 식당 18시 예약, B 전망대 18시 10분 예약인데 이동에 30분 소요) 입력 시, "가능한 루트가 없습니다"가 아닌 "A와 B 장소의 예약 시간이 겹쳐 이동이 불가능합니다. 시간을 수정해 주세요"라고 충돌 지점을 정확히 짚어 안내.

## 4. 핵심 기술 및 알고리즘 명세 (Core Tech)

**1) 다중 제약 조건 탐색 (Multi-Constraint Search)**

* **Hard Constraint (절대 고정):** 사용자가 직접 입력한 예약 시간 및 장소 운영 종료 시간. 위반 시 해당 동선 경우의 수 폐기(Drop).
* **Soft Constraint (가산점):** 특정 장소에 설정된 베스트 타임. 충족 시 동선 점수에 가산점 부여.
* **식당 Context-Aware 배치:** 장소가 '식당'일 경우, 강제로 점심(11:30~13:30) 또는 저녁(17:30~19:30) 슬롯에만 들어가도록 알고리즘 통제.

**2) 대중교통 투 트랙(Two-Track) 라우팅 알고리즘**
120개(5곳 기준)의 경로를 실시간 대중교통 API로 모두 조회할 경우 발생하는 속도 저하 및 API 호출 제한을 막기 위한 2단계 로직.

* **Track 1 (순서 확정용 가계산):** 거리에 비례하는 '평균 정적 소요 시간'을 고정값으로 사용하여 120개의 방문 순서 중 최적의 경로 1개를 0.1초 만에 도출.
* **Track 2 (실제 타임라인 생성용 정밀 호출):** 확정된 단 1개의 최적 경로를 바탕으로, 각 장소의 체류 시간과 도착 시간을 계산해가며 순차적으로 '동적 길찾기 API'를 호출. 이를 통해 빠르면서도 정확한 환승/노선 스텝(Step-by-step) 데이터를 UI에 제공.

---

## 5. 추천 기술 스택 및 배포 (Tech Stack)

* **Frontend:** React 또는 Vanilla JS (모바일 웹앱 뷰 최적화, GitHub Pages 또는 Vercel 배포)
* **Database (투표/실시간 동기화):** Firebase Firestore (서버 없이 실시간 소셜 렌더링 구현)
* **Backend / Algorithm:** Python (FastAPI 또는 Flask) - 복잡한 시간 연산 및 투 트랙 알고리즘 처리
* **External APIs:** 카카오/네이버 모빌리티 API (이동 거리 및 대중교통 길찾기 노선), Google Places API (영업시간 파악)

---

## 6. 심사위원 어필 포인트 요약 (Competitive Advantage)

*"기존 앱은 단순 거리순 정렬이나 수동 시간 편집만 지원하지만, SyncTrip은 다수의 인원이 투표로 장소를 고르고, 식당 예약 시간이나 영업 종료 시간 같은 '시간 제약(Constraint)'을 수학적 알고리즘으로 풀어냅니다. 특히 대중교통 길찾기의 정확도와 속도를 동시에 잡은 'Two-Track 알고리즘'과 '하이브리드 정보 입력(API+수동)'을 통해 대학생의 실제 여행 기획 방식을 완벽히 소프트웨어로 구현했습니다."*
